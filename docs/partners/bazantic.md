# Bazantic — making the paid API usable by an agent that has never seen it

Tracks: **Agentify a New API** and **Best Recipe Using EthGlobal Hackathon Sponsor APIs**.
Status: **API side ready** — the resource is live and describes itself; the Bazantic account,
Gateway and Recipe are the remaining steps and need a bazantic.com login.

## What we bring

A paid API that already exists and already works:

```
GET https://api.sowee.site/v1/market/insights
→ 402, PAYMENT-REQUIRED: base64 x402 challenge
   scheme exact · network hedera:testnet · asset 0.0.429274 (USDC)
   amount 10000 (0.01 USDC) · payTo 0.0.7162116 · feePayer 0.0.7162784
```

Settle the challenge and repeat the call, and it answers with every invoice bond listed on
Sowee: how much of each is funded, how long it has left, and what the issuance discount
annualises to. Payments are verified and settled by the Blocky402 facilitator, and each receipt
is anchored to a public Hedera Consensus Service topic
([`0.0.10388277`](https://hashscan.io/testnet/topic/0.0.10388277)), so a payer can prove what
they bought without trusting us.

This is not an API written for the prize. It is the endpoint our own agent pays for before it
decides which bond to fund ([`apps/agent`](../../apps/agent)), which is the honest test of
whether the data is worth money: something already acts on it.

## Why it is a candidate for "a new API"

It cannot have been on Bazantic at the start of the event — it did not exist. The service was
written during ETHOnline 2026 and only became publicly reachable on 7 September, when
`api.sowee.site` was cut over to this build.

## The spec

The API describes itself at **<https://api.sowee.site/openapi.json>** — OpenAPI 3.1, generated by
the running process rather than checked in, so it cannot drift from the service. It names the
paid operation, the price, the response shape, and the 402 a caller has to handle before it can
pay. The `servers` URL follows the request, so the document is correct behind the proxy.

## What an agent gets out of it that a raw call does not

A recipe's value is in saying *when* to reach for this, and what to do with the answer. Ours has
a shape worth writing down:

- **When.** The caller wants to put stablecoins to work for a fixed, short tenor against real
  invoices rather than a lending pool rate. Every bond quotes a discount and a maturity, so the
  comparison is arithmetic, not narrative.
- **What to read.** `impliedAprBps` ranks the offers, `fundedPct` says how much room is left in
  each, and `tenorDays` says how long the money is committed. `best` is the highest implied APR
  with capacity remaining.
- **What it costs to be wrong.** These are testnet assets and the bonds are demonstrations. The
  compliance layer is not: an agent that buys must hold a wallet that passed the same KYC a human
  does, or the transfer reverts in the token itself.
- **What to do next.** Size an order against remaining capacity and the wallet's balance, then
  fund it on `InvoiceMarket`. Our agent does exactly this with `--execute`.
